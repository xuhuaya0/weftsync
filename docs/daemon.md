# 常驻进程（daemon）

```powershell
weftsync daemon jobs/nightly.toml                # 按调度跑
weftsync daemon jobs/*.toml --run-now            # 先立刻跑一遍
weftsync daemon jobs/a.toml --addr 127.0.0.1:5600 --log-file daemon.log
```

---

## 1. 调度

写在第个作业文件的 `[job.schedule]` 里：

```toml
[job.schedule]
mode = "interval"        # interval | daily_time | cron（不写 = 只能手动触发）
interval = "1h"
start_at = "08:00"
align_to_start = true
```

| `mode` | 必填 | 行为 |
|---|---|---|
| （不写） | — | **只响应手动触发**，永不自作主张 |
| `interval` | `interval` | 每隔这么久跑一次（最小 `1m`） |
| `daily_time` | `daily_time` | 每天本地时间 `HH:MM` 跑一次 |
| `cron` | `cron` | 标准五字段表达式 |

**`align_to_start`**：只在 `interval` 下有意义，且必须配 `start_at`。

| `align_to_start` | `interval = "2h"`、`start_at = "08:00"` 时的实际时刻 |
|---|---|
| `true` | 08:00、10:00、12:00…（**锚定时刻**，重启也不漂移） |
| `false` | 从进程启动那一刻起每 2 小时（重启就会漂） |

**为什么不接受 `@daily` 这类描述符**：读回配置时它是有歧义的，本项目要求配置一眼能看懂。

## 2. 本地 HTTP API

只绑 `127.0.0.1`。传 `0.0.0.0`、局域网地址或 `:5572`（空主机）会**直接拒绝**：
这个 API 能启动同步且没有认证，放到网络上等于把云盘交出去。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/status` | 每个作业的状态、调度、下次/上次运行、上次结果 |
| POST | `/api/run?job=名称` | 立刻启动一个作业 |
| POST | `/api/run` | 启动所有启用的作业 |
| GET | `/api/config?job=名称` | 读取可编辑的配置视图 |
| POST | `/api/config?job=名称` | 保存配置（写回 job 文件并立即 reload） |
| GET | `/api/autostart` | 开机自启状态（是否启用、写在哪、命令是什么、是否与当前进程一致） |
| POST | `/api/autostart` | `{"enabled":true|false}` 打开/关闭开机自启 |
| GET | `/api/health` | 存活检查 |

`/api/status` 示例：

```json
{
  "jobs": [{
    "name": "nightly",
    "state": "idle",
    "enabled": true,
    "pairs": 2,
    "schedule": "every 2h0m0s from 08:00",
    "next_run": "2026-11-07T18:00:00+08:00",
    "last_run": "2026-11-07T16:00:03+08:00",
    "last_ok": true,
    "skipped": 0,
    "last_result": [{"Pair":"work","Actual":{"Transferred":3,"Deleted":0}}]
  }],
  "now": "2026-11-07T17:12:00+08:00"
}
```

`state`：`idle` / `running` / `disabled`。
`skipped`：因为上一轮还没结束而被跳过的次数。

## 3. 单实例

**监听端口本身就是单实例锁。** 第二个 daemon 绑同一地址会立刻失败：

```
daemon: 127.0.0.1:5572 is already in use, which normally means another
weftsync daemon is running. Stop it first, or pass a different --addr
```

比 pid 文件可靠：进程崩了端口自动释放，不会留下需要人手工清理的残留锁。
想跑两个 daemon（不同作业、不同端口）是可以的，显式传 `--addr` 即可。

---

## 4. 防重叠

同一个作业上一轮还没结束，不会再起一轮：

- 定时触发：**跳过并计数**（`skipped`），日志里写一行原因
- API 触发：返回 **HTTP 409**，说明「已经在跑」

不同作业之间互不影响，可以并行。

---

## 5. 停止

`Ctrl+C`（或 `SIGTERM`）→ 停止调度 → **等进行中的那轮跑完** → 退出。

**不会**在中途强杀上传：飞书没有 abort 接口，分片上传断开后只能等它 24 小时自动过期。
让它跑完比留下一个半成品更好。

---

## 6. 与删除保护的关系

daemon **只决定什么时候跑**，不改变任何一个 pair 的安全规则：
`max_delete` 闸门、`deletion` 档位、`conflict` 策略全部照旧生效。
定时任务和人手动跑走的是同一条 `job.Run` 路径 —— 不存在「自动跑就宽松一点」的分支。

## 7. 网页界面

浏览器打开 `http://127.0.0.1:5572`（或你传的 `--addr`）即可。页面**内嵌在二进制里**，
不需要额外文件，也不需要构建步骤 —— 双击就能用。

五个页签：

| 页签 | 内容 |
|---|---|
| **作业** | 每个作业的状态（空闲/运行中/已停用）、调度描述、下次与上次时间、上次结果、`立即运行` 按钮 |
| **配置** | 选中作业后可直接改：启用、变体、调度、默认同步设置、每个 pair 的完整字段；可增加/删除 pair |
| **冲突** | 各作业最近一次运行报出的冲突（路径 + 类型 + 说明） |
| **历史** | 最近 100 次运行：开始时间、耗时、结果、上传数、删除数、是否熔断、错误信息 |
| **日志** | 最近 500 行调度器日志，可自动滚动 |

页面每 3 秒轮询一次自己的 API。**数据没变时不重绘** —— 之前每轮整体重绘会把
`立即运行` 按钮换掉，点击会被吞掉、按钮也没法停留在「已启动」状态。

数据都来自同一套接口：

| 接口 | 用途 |
|---|---|
| `GET /api/status` | 作业状态 + 上次结果 |
| `GET /api/history` | 运行历史（环形缓冲，最近 100 条） |
| `GET /api/log` | 最近日志（环形缓冲，最近 500 行） |
| `POST /api/run` | 立即运行 |
| `GET /api/config?job=` | 可编辑的配置视图 |
| `POST /api/config?job=` | 保存配置 |

历史与日志都是**固定容量环形缓冲**：无人值守跑几周，无界切片会一路长到进程被 OOM 杀掉。

### 配置页与保存语义

保存不是「把表单写下去」，而是四件事：

1. **在上一份配置上叠加**，而不是从零构造。表单渲染不了的字段（`max_delete_size`）
   因此不会被静默抹掉。
2. 用「提交值 vs 当初展示给用户的值」判断**用户是否真的改过**。没改就原样保留：
   显式仍显式、继承仍继承。否则第一次保存会把「继承默认」固化成「显式等于今天的默认」，
   以后改默认值就跟不上了。
3. **校验在写盘之前**，且与 `Load` 用同一套规则。`validate()` 里包含调度校验，
   所以能保存的文件一定能被启动（之前 `Save` 不看调度，能存进 `start_at = "10m"`，
   下次启动直接退出）。
4. 写 `.bak` 后原子写（tmp + fsync + rename），然后**立即 reload**，下一轮同步就用新设置。

**注释会丢**。编码器是手写的紧凑 TOML 写出器（结构体编码器会把每个零值字段都写出来，
不可读）。只写非空字段，所以**空行位置与字段顺序会变**，但那些不承载意图；
真正会丢的是注释。文件里有注释时保存会返回 `ErrLossyRewrite`，界面先警告并要求确认。
无论哪种情况，旧内容都保留为 `.bak`。

运行中的作业**拒绝保存**：改动会作用到已经开跑的那一轮。

## 8. 开机自启

界面「设置」页签有一个开关。写的是**当前正在运行的这个命令**，不是让用户重新拼一条命令行。

| 平台 | 位置 | 形态 |
|---|---|---|
| Windows | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 值 `weftsync` | `REG_SZ` 命令字符串 |
| Linux | `$XDG_CONFIG_HOME/autostart/weftsync.desktop`（默认 `~/.config/autostart/`） | Desktop Entry，`Exec=` 一行 |

**只写 HKCU / 用户目录**：开机自启是单用户便利，不该要管理员权限，也不该影响别的用户。

### 为什么路径必须转成绝对路径

登录时的工作目录没有意义。用相对路径 `job.toml` 写进启动项，登录后会在某个系统目录里
找这个文件 —— 找不到，或者找到别的同名文件。**启动项看起来正确，每天早上静默失败。**

所以 `SpecFromInvocation` 把可执行文件、每个作业文件、`--log-file`、`--config` 全转绝对路径。
实测证据：把注册表里那条命令**在 `C:\` 下原样执行**，`/api/health` 返回 200，
`/api/status` 照常列出作业 —— 换工作目录不影响。

### 只记录偏离默认值的参数

`--addr` 等于默认值时**不写进去**。写了就等于把当时的默认值冻结下来：
以后默认值变了，这条老启动项还传着旧值，而用户以为自己用的是默认。

### 引号

- Windows 用 `syscall.EscapeArg`（和 `CreateProcess` 同一套规则）。路径带空格却不加引号，
  是把程序放进 `C:\Program Files` 之后启动项失效的经典原因。
- Linux 两层转义要嵌套：先按值规则把 `\` 写成 `\\`，再按引号规则把 `"` `` ` `` `$`
  转义，并且字面 `%` 要写成 `%%`。只做其中一层，带空格的路径会被拆成多个参数。

### 状态里的 `matches`

`matches: false` 表示**入口存在，但跑的不是这个进程的命令**（换了可执行文件位置、
换了作业文件）。界面上这单独提示一句，并说明「重新勾选一次会覆盖它」——
只说「已启用」是正确但会误导的。
