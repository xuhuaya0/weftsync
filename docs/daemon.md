# 常驻进程（daemon）

```powershell
weftsync daemon jobs/nightly.toml                # 按调度跑
weftsync daemon jobs/*.toml --run-now            # 先立刻跑一遍
weftsync daemon jobs/a.toml --addr 127.0.0.1:5600 --log-file daemon.log
```

---

## 1. 调度

写在第个作业文件的 `[job.schedule]` 里：

```toml
[job.schedule]
mode = "interval"        # interval | daily_time | cron（不写 = 只能手动触发）
interval = "1h"
start_at = "08:00"
align_to_start = true
```

| `mode` | 必填 | 行为 |
|---|---|---|
| （不写） | — | **只响应手动触发**，永不自作主张 |
| `interval` | `interval` | 每隔这么久跑一次（最小 `1m`） |
| `daily_time` | `daily_time` | 每天本地时间 `HH:MM` 跑一次 |
| `cron` | `cron` | 标准五字段表达式 |

**`align_to_start`**：只在 `interval` 下有意义，且必须配 `start_at`。

| `align_to_start` | `interval = "2h"`、`start_at = "08:00"` 时的实际时刻 |
|---|---|
| `true` | 08:00、10:00、12:00…（**锚定时刻**，重启也不漂移） |
| `false` | 从进程启动那一刻起每 2 小时（重启就会漂） |

**为什么不接受 `@daily` 这类描述符**：读回配置时它是有歧义的，本项目要求配置一眼能看懂。

## 2. 本地 HTTP API

只绑 `127.0.0.1`。传 `0.0.0.0`、局域网地址或 `:5572`（空主机）会**直接拒绝**：
这个 API 能启动同步且没有认证，放到网络上等于把云盘交出去。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/status` | 每个作业的状态、调度、下次/上次运行、上次结果、**当前进度** |
| POST | `/api/run?job=名称` | 立刻启动一个作业 |
| POST | `/api/run?job=名称&plan=true` | **只预览**：测出会改什么，什么都不改 |
| POST | `/api/run` | 启动所有启用的作业 |
| POST | `/api/stop?job=名称` | 请求停止正在跑的那一轮（202；没在跑时 409） |
| GET | `/api/config?job=名称` | 读取可编辑的配置视图 |
| GET | `/api/log?level=&contains=&limit=&since=` | 日志（服务端过滤） |
| GET | `/api/log/export?level=&contains=` | 把过滤后的日志作为文本附件下载 |
| POST | `/api/conflict/resolve?job=&pair=&path=&action=push\|pull` | 处理一条冲突 |
| GET | `/api/autostart` | 开机自启状态（是否启用、写在哪、命令是什么、是否与当前进程一致） |
| POST | `/api/autostart` | `{"enabled":true|false}` 打开/关闭开机自启 |
| GET | `/api/info` | 这个进程实际在用什么：版本（构建时的 git 提交）、平台、监听地址、启动时间/已运行、加载的作业文件、rclone 配置路径、拆分账本目录、缓冲大小 |
| GET | `/api/settings` | 全局设置（通知开关、过滤规则）|
| POST | `/api/settings` | 保存全局设置，立即生效 |
| GET | `/api/health` | 存活检查 |

`/api/status` 示例：

```json
{
  "jobs": [{
    "name": "nightly",
    "state": "idle",
    "enabled": true,
    "pairs": 2,
    "schedule": "every 2h0m0s from 08:00",
    "next_run": "2026-11-07T18:00:00+08:00",
    "last_run": "2026-11-07T16:00:03+08:00",
    "last_ok": true,
    "skipped": 0,
    "last_result": [{"Pair":"work","Actual":{"Transferred":3,"Deleted":0}}]
  }],
  "now": "2026-11-07T17:12:00+08:00"
}
```

`state`：`idle` / `running` / `disabled`。
`skipped`：因为上一轮还没结束而被跳过的次数。

## 3. 单实例

**监听端口本身就是单实例锁。** 第二个 daemon 绑同一地址会立刻失败：

```
daemon: 127.0.0.1:5572 is already in use, which normally means another
weftsync daemon is running. Stop it first, or pass a different --addr
```

比 pid 文件可靠：进程崩了端口自动释放，不会留下需要人手工清理的残留锁。
想跑两个 daemon（不同作业、不同端口）是可以的，显式传 `--addr` 即可。

## 4. 防重叠

同一个作业上一轮还没结束，不会再起一轮：

- 定时触发：**跳过并计数**（`skipped`），日志里写一行原因
- API 触发：返回 **HTTP 409**，说明「已经在跑」

不同作业之间互不影响，可以并行。

## 5. 停止

有两条路，语义不同：

| 场景 | 行为 |
|---|---|
| **关掉 daemon**（`Ctrl+C` / `SIGTERM` / 托盘「退出」） | 停止调度 → **取消正在跑的那一轮** → 等它退出 → 退出进程 |
| **界面「停止」按钮**（`POST /api/stop`） | 只取消那**一轮**，daemon 继续跑 |

> 这两条其实走的是**同一个机制**：作业的 context 派生自 daemon 的 context，
> 所以关 daemon 就会中断传输。早先这里写的是「等进行中的那轮跑完」—— 
> **是错的**，2026-11-08 在 WSL 上实测确认：第一次 `SIGINT` 后日志立刻出现
> `Removing partially written file on error: context canceled`。
> 文档写了很久没被发现，因为它描述的是一种「看上去更安全」的行为。

中断是安全的：飞书没有 abort 接口，但**分片上传不走 `upload_finish` 就不会提交**，
所以云端不会出现半截文件（实测：停掉 24MiB 上传后远端文件数仍为 0）。
一次性 `upload_all` 本来就是整文件原子提交。代价是已发出的分片白传了 ——
取消就是取消，不承诺可续（D45）。

### 关 daemon 时的两次信号

| 次 | 行为 |
|---|---|
| 第一次 | 打印 `stopping <作业名>; press Ctrl+C again to exit immediately`，取消作业开始收尾 |
| 第二次 | 打印 `second signal, exiting without waiting` 并立即 `os.Exit(1)` |

用 `signal.NotifyContext` 做不到这一点：它会把后续每一个信号都吞掉，
卡住的传输就没有出路了（只能杀进程）。所以这里手工计数信号。

实测（WSL，4/4）：作业运行中 → `kill -INT` → 日志出现上面那行；
作业确实被中断（partial 文件被清掉）；进程随后自行退出。
**第二次信号那一条没有构造出真实的卡死场景来验证** —— 代码在，但只在传输
真的不返回时才会走到。

停止**不算失败**：`last_stopped = true`、`last_ok = true`、错误信息为空，
历史里标「已停止」。把它记成失败会让人去找一个并不存在的问题。

### 怎么判断「是被停的」而不是「出错了」

看 **自己的 context**（`runCtx.Err()`），不看 `job.Run` 返回的 error。
实测：rclone 在 context 被取消时**可能返回 nil**（本地后端就是这样），
所以靠返回的 error 分类会时对时错。

## 6. 与删除保护的关系

daemon **只决定什么时候跑**，不改变任何一个 pair 的安全规则：
`max_delete` 闸门、`deletion` 档位、`conflict` 策略全部照旧生效。
定时任务和人手动跑走的是同一条 `job.Run` 路径 —— 不存在「自动跑就宽松一点」的分支。

## 7. 网页界面

浏览器打开 `http://127.0.0.1:5572`（或你传的 `--addr`）即可。页面**内嵌在二进制里**，
不需要额外文件，也不需要构建步骤 —— 双击就能用。

五个页签：

| 页签 | 内容 |
|---|---|
| **作业** | 状态（空闲/运行中/已停用）、**实时进度**、调度、下次/上次时间、上次结果；每行 `预览` / `立即运行`，运行中变 `停止` |
| **配置** | 选中作业后可直接改：启用、变体、调度、默认同步设置、每个 pair 的完整字段；可增加/删除 pair |
| **冲突** | 各作业最近一次运行（或最近一次预览）报出的冲突；每行两个按钮：以本地为准 / 以云端为准 |
| **历史** | 最近 100 次运行：开始时间、耗时、结果（成功 / 失败 / **预览** / **已停止**）、上传数、删除数、是否熔断、错误信息 |
| **日志** | 最近 500 行；可按住级别筛选、搜索、导出（导出内容跟随当前过滤） |
| **设置** | 开机自启（见 §8）、远程凭据（见 §9） |

轮询间隔**自适应**：有作业在跑时 1 秒，否则 3 秒。

**数据没变时不重绘** —— 之前每轮整体重绘会把按钮换掉，点击被吞。
**进度数字不进重绘判据**：它每秒都在变，重绘会让「停止」按钮在鼠标下消失。
进度写进已经存在的 span，按钮保持不动。

### 预览面板

点 `预览`（或未勾「跳过预览」时的 `立即运行`）→ 面板打开，逐 pair 列出：
上传/覆盖多少个、多少字节、删除多少项、冲突多少个，以及**这次真跑会不会被
`max_delete` 拦住**。面板里的 `按此执行` 才真的跑。

预览**失败时会显式报错**（`plan.error`）：失败和「没有变更」都是全零计数，
不加这一条界面就会把「磁盘打不开」说成「没有需要变更的内容」（实测踩到过）。
预览失败时 `按此执行` 置灰。

数据都来自同一套接口：

| 接口 | 用途 |
|---|---|
| `GET /api/status` | 作业状态 + 上次结果 + 当前进度 + 最近一次预览 |
| `GET /api/history` | 运行历史（环形缓冲，最近 100 条） |
| `GET /api/log` | 最近日志（环形缓冲，最近 500 行） |
| `POST /api/run` | 立即运行（`&plan=true` 则只预览） |
| `POST /api/stop` | 停止运行中的那一轮 |
| `GET /api/config?job=` | 可编辑的配置视图 |
| `POST /api/config?job=` | 保存配置 |
| `GET /api/log?level=&contains=&limit=&since=` | 日志（服务端过滤，级别由文本推断） |
| `GET /api/log/export?level=&contains=` | 过滤后的日志，作为 `attachment` 文本下载 |
| `POST /api/conflict/resolve?job=&pair=&path=&action=` | 处理一条冲突（`push` / `pull`） || GET | `/api/credentials` | 配置文件里的远程、字段、使用它的作业（**永不返回密钥**） |
| POST | `/api/credentials?name=` | 保存字段（密钥写入前混淆；`""` 清除，`null` 不动） |
| POST | `/api/credentials/test?name=` | 真实认证 + 列根目录，验证这份凭据能用 |
历史与日志都是**固定容量环形缓冲**：无人值守跑几周，无界切片会一路长到进程被 OOM 杀掉。

### 日志过滤为什么要放在服务端

缓冲区是固定的 500 行窗口。在浏览器里过滤意味着「这一轮的错误」可能在过滤器看到之前
就被挤掉了 —— 用户搜到的是空，而错误确实发生过。所以 `level` / `contains` 都在
`logSink.Filtered` 里做，`since=<seq>` 还能只取新增的行。

日志级别是**从文本里读出来的**：`logf` 没有级别，rclone 的输出也只是纯文本，
没有结构化字段可挂。认不出的行一律归为 `info` —— 漏掉一条日志比错误地隐藏一条更糟。

导出的文件名带时间戳（`weftsync-20260101-120000.log`），并带
`Content-Disposition: attachment`：让人下载的是文件，而不是在浏览器里渲染一屏等宽文字。

### 冲突处理：两个按钮，都不删云端

| 动作 | 做了什么 | 不可逆风险 |
|---|---|---|
| **以本地为准** (`push`) | 只改同步快照：删掉这条路径的记录。下次运行会上传本地文件覆盖远端那一份 | 无（云端此刻不变） |
| **以云端为准** (`pull`) | 把远端那份**下载覆盖本地文件**，然后把远端 token + 本地指纹记为基线 | 本地那份未上传的修改会丢（所以界面会先确认） |

为什么不提供第四个「忽略」按钮：一条冲突只有两种结局 —— 要么本地赢，要么远端赢。
真正的「忽略」等于「以后每次运行都继续报这个冲突」，那是噪音而不是解决。
想在云端同时保留两份，用 pair 级的 `conflict = "keep-both"`（同步路径里已实现并测试）。

为什么 `pull` 必须先下载再记账：快照里的本地指纹表示「远端确实有这个内容」。
只改指纹不下载，快照就在宣称一次从未发生的上传，下一次比较会基于假数据。
下载后还会把本地 mtime **截断到整秒** —— 快照存的是秒，不截断会让下一次运行
认为文件变了，于是一传一传没完（`truncateMTime` 有单测）。

`adopt` 还会**校验 token 当前确实在文件夹里**：否则快照会与远端不一致，
冲突马上又回来，而快照已经指向一个不存在的东西。

分辨率命令的路径走 `-o path=`，不是位置参数：rclone 会把位置参数当成目录（Fs）解析，
`backend resolve remote:a.txt` 会被拒为 `is a file not a directory`（实测）。

### 配置页与保存语义

保存不是「把表单写下去」，而是四件事：

1. **在上一份配置上叠加**，而不是从零构造。表单渲染不了的字段（`max_delete_size`）
   因此不会被静默抹掉。
2. 用「提交值 vs 当初展示给用户的值」判断**用户是否真的改过**。没改就原样保留：
   显式仍显式、继承仍继承。否则第一次保存会把「继承默认」固化成「显式等于今天的默认」，
   以后改默认值就跟不上了。
3. **校验在写盘之前**，且与 `Load` 用同一套规则。`validate()` 里包含调度校验，
   所以能保存的文件一定能被启动（之前 `Save` 不看调度，能存进 `start_at = "10m"`，
   下次启动直接退出）。
4. 写 `.bak` 后原子写（tmp + fsync + rename），然后**立即 reload**，下一轮同步就用新设置。

**注释会丢**。编码器是手写的紧凑 TOML 写出器（结构体编码器会把每个零值字段都写出来，
不可读）。只写非空字段，所以**空行位置与字段顺序会变**，但那些不承载意图；
真正会丢的是注释。文件里有注释时保存会返回 `ErrLossyRewrite`，界面先警告并要求确认。
无论哪种情况，旧内容都保留为 `.bak`。

运行中的作业**拒绝保存**：改动会作用到已经开跑的那一轮。

## 8. 开机自启
界面「设置」页签有一个开关。写的是**当前正在运行的这个命令**，不是让用户重新拼一条命令行。

| 平台 | 位置 | 形态 |
|---|---|---|
| Windows | `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 值 `weftsync` | `REG_SZ` 命令字符串 |
| Linux | `$XDG_CONFIG_HOME/autostart/weftsync.desktop`（默认 `~/.config/autostart/`） | Desktop Entry，`Exec=` 一行 |

**只写 HKCU / 用户目录**：开机自启是单用户便利，不该要管理员权限，也不该影响别的用户。

### 为什么路径必须转成绝对路径

登录时的工作目录没有意义。用相对路径 `job.toml` 写进启动项，登录后会在某个系统目录里
找这个文件 —— 找不到，或者找到别的同名文件。**启动项看起来正确，每天早上静默失败。**

所以 `SpecFromInvocation` 把可执行文件、每个作业文件、`--log-file`、`--config` 全转绝对路径。
实测证据：把注册表里那条命令**在 `C:\` 下原样执行**，`/api/health` 返回 200，
`/api/status` 照常列出作业 —— 换工作目录不影响。

### 只记录偏离默认值的参数

`--addr` 等于默认值时**不写进去**。写了就等于把当时的默认值冻结下来：
以后默认值变了，这条老启动项还传着旧值，而用户以为自己用的是默认。

### 引号

- Windows 用 `syscall.EscapeArg`（和 `CreateProcess` 同一套规则）。路径带空格却不加引号，
  是把程序放进 `C:\Program Files` 之后启动项失效的经典原因。
- Linux 两层转义要嵌套：先按值规则把 `\` 写成 `\\`，再按引号规则把 `"` `` ` `` `$`
  转义，并且字面 `%` 要写成 `%%`。只做其中一层，带空格的路径会被拆成多个参数。

### 状态里的 `matches`

`matches: false` 表示**入口存在，但跑的不是这个进程的命令**（换了可执行文件位置、
换了作业文件）。界面上这单独提示一句，并说明「重新勾选一次会覆盖它」——
只说「已启用」是正确但会误导的。

## 8.5 远程凭据

「设置」页签的下半部分是凭据。它编辑的就是 **rclone 启动时用的那个配置文件**，
不接受任何来自请求的路径——否则一个凭据表单就变成了任意文件写入。

### 密钥永不回显

不是「遮住显示」、不是「只显示后四位」，而是**根本不返回**。一个遮罩值会让人以为
控制台知道这个密钥，而部分值本身就是泄露。

显示的是：是否已设置、**字符长度**、以及存储形态是否为 rclone 的模糊形式。
长度这一项确实有用：多打进去的空格或一个换行是「凭据看着对却认证失败」最常见的原因，
没有它这个页面帮不上忙。

### 三种提交语义

| 提交的值 | 含义 |
|---|---|
| 字段没出现在 `values` 里 | 不修改 |
| `""` | 清除这个键 |
| 有内容 | 覆盖（两端空白会被去掉） |

这就是「半填一张表再提交」安全的原因：只改你想改的。

### 写盘前先混淆

密码类字段（`IsPassword`）在写入前用 rclone 的模糊编码处理，文件里不会出现明文。
写完把文件权限收紧到 `0600`（Unix；Windows 上文件在用户目录内）。

### 「测试连接」为什么真的列一次目录

只取 token 只能证明 app 凭据对；`root_token` 是另一半配置。列一次根目录同时覆盖两者，
而且这正是下一轮同步要做的第一件事——通过这里就意味着下一次运行能过第一步。

### 字段从后端自己的选项表来

不是硬编码飞书那三个字段：`fs.Find(type).Options` 决定表单长什么样。所以换一个后端类型，
页面照样能显示它的必填项，密钥字段也照样被识别（`IsPassword`）。

## 9. 系统托盘（仅 Windows）

加 `--tray` 才启用。图标用像素现画（不打包 `.ico`，二进制还是单文件），
**没有任何 cgo**，所以从 Linux 交叉编译照样能出带托盘的 Windows 程序。

| 操作 | 行为 |
|---|---|
| 双击左键 / 菜单「打开控制台」 | 用默认浏览器打开 `http://<addr>/` |
| 菜单「立即运行全部」 | 对每个启用的作业调一次 `Trigger`（异步，不阻塞消息线程） |
| 菜单「退出」 | 与 Ctrl+C 同一条关闭路径 |
| 悬停 | 显示提示文字 |

`--tray` 会被记录进开机自启的命令里 —— 否则打开自启后重启，图标就悄悄没了。

### 「托盘坏掉不能带走 daemon」

这条是硬约束，落实在两处：

1. `Start` 返回 error ⇒ 命令里打印一行 `tray: ... (continuing without an icon)` 后**继续跑**。
   没有通知区域（服务会话、Explorer 没起）是正常情况。
2. 消息线程用了 `recover`。第一版就因为把 GDI 函数写成 `user32`（实际在 `gdi32`）
   在 goroutine 里 panic，把整个进程带下去了 —— `syscall.LazyProc.Call` 在找不到
   函数时是 **panic 而不是返回 error**，这一类错误只有 recover 兜得住。

实测：用 `taskkill`（不带 `/F`）向进程发 `WM_CLOSE` 把托盘窗口打掉，daemon 仍在，
`/api/health` 仍返回 200 —— 只是图标没了。

### 通知：只发该发的三种

托盘启动成功后 daemon 才安装通知回调（`Daemon.SetNotifier`）。定时运行无人值守，
所以这几种情况会弹气泡：**运行失败**、**被闸门拦下**、**有冲突未处理**。

**成功、预览、用户手动停止都不发。** 每次成功都弹等于训练用户关掉通知，
真正要命的那条也就没人看了。

每条通知同时写一行 `notify: <标题>` 到日志 —— 气泡会消失，日志要能回答
「我到底有没有被告知过」。没有托盘（Linux、无头服务器、`--tray` 没加）时
回调是 nil，`notifyf` 直接返回，不产生第二条失败路径。

### Linux 为什么没有

X11 托盘要 C 库，Wayland 根本没有托盘协议，AppIndicator 要库 + 桌面扩展。
与其做一个「某些桌面能用、某些静默不出现」的东西，不如明确不支持：
Linux 上用浏览器打开同一个地址。

## 10. 目录拆分

飞书云盘单个目录最多 1500 个直接子项（文件 + 子目录合计）。超过就上传失败，
而且失败点在同步中途，已经传上去的部分留在云端。F7 的做法是**在同步之前拦下**，
让用户选一种拆法，然后按账本移动本地和云端。

### 上限取 1400，不是 1500

硬限是飞书定的，我们按 1400 拦。留 100 的余量是因为检查和执行不是同一瞬间：
预检看到 1450 项、你点确认、它真的开始移文件，中间照样可能有新文件落地。
余量为 0 时会出现「检查通过、同步却报超限」这种最难解释的情况。

### 四条接口

| 接口 | 作用 |
|---|---|
| `GET /api/split/precheck?job=&pair=&dir=` | 列出所有超过 1400 项的直接目录，并给出默认拆分目录名 |
| `GET /api/split/plan?job=&pair=&dir=&scheme=&max=` | 算一份方案（只读，不动任何文件） |
| `POST /api/split/execute?...&confirm=<目录名>` | 真执行。`confirm` 必须等于目录名，在根目录时填 `root` |
| `GET /api/split/snapshots?job=&pair=` | 列出账本 |
| `POST /api/split/undo?job=&pair=&snapshot=<路径>` | 按账本移回原位 |

`confirm` 不是形式主义：`execute` 会移动本地文件，而 HTTP 请求可能被误点、被重放、
被curl 脚本重复调用。要求把目录名打一遍，就把「误操作」的成本拉到和收益相当。
缺少或不对时返回 422，**一个文件都不会动**。

### 四种拆法

| 方式 | 结果 | 适用 |
|---|---|---|
| `type` 按文件类型 | `_pdf` / `_png` / `_xlsx` / `_noext` | 目录里格式混杂、天然分成几大堆 |
| `initial` 按首字母 | `A-H` / `I-P` / `Q-Z` / `0-9` / `_other` | 文件名是编号或英文，分布均匀 |
| `year` 按修改年份 | `2026-01` / `2026-02` … | 有明确时间线，拆分后还能当归档用 |
| `count` 按数量均分 | `part-01` / `part-02` … | 上面三种都不均匀时的保底 |

任何一个桶超过上限会自动**再分到同级的 `-01`/`-02`**（如 `Q-Z-01`、`Q-Z-02`），
不往下嵌套 —— 飞书限 15 层，拆分本身就在制造层级，不能再白送一层。

`initial` 对非 ASCII 文件名一律归 `_other`，**不做拼音首字母**。
拼音要么引一个几 MB 的词库，要么只能覆盖常用字，两种都会在某天给出
「张、李 明明都在，却被扔进 _other」的意外。归堆错只是难看，猜错字是错误。

### 执行顺序，以及为什么本地在前

```
快照 → 移动本地 → 建云端目录 → 移动云端 → 校验 → 重写同步状态
```

本地先动，因为本地重命名是毫秒级、失败能立刻回滚；云端移动受接口限速影响，
慢且中途失败概率高。把「可能失败的那一步」放在后面，意味着前面的失败永远
可以低成本退回去。

云端移动**不复用本地路径**，而是走 feishu 后端的 `repath` 命令：飞书的文件有
`file_token`，移动本质是改 token 的父目录，不需要重新上传。代价是状态文件里的
key 必须跟着改，否则下次同步会把它当成新文件再传一遍（详见 D40）。

两个移动阶段都是**幂等**的：源不存在而目标存在 → 当作「已经做过」。
这不是洁癖 —— 账本每 25 次云端移动落一次盘，进程在此期间被杀，重启后必然
出现「一半做过、一半没做」的状态。

### 撤销

撤销按账本反向走：先云端、后本地、再删空的桶目录。云端在前是因为它更可能失败：
云端没撤成功就动本地，会留下「本地已还原、云端还是拆开的」——这种状态下
再点一次同步会把文件又搬回桶里，看起来像撤销失效。

账本里 `undone` 是单独的字段，不复用 `completed=false`：一个 undo 过的账本
每一项的 `LocalDone`/`RemoteDone` 都是 false，和「中途被打断」的状态一模一样。
分不开的话，界面会把用户主动撤销的拆分报成「未完成（剩 1450）」，还提供「继续」。

### 定时任务永远不自动拆

`job.RunPair` 在真跑之前做预检，超限直接返回 `OverLimitError`，同步**一个文件都不上传**。
定时任务撞上这种情况只会在历史里留一条失败记录。理由：拆分是移动用户本地文件的操作，
无人值守时做这件事，风险远大于「这次没同步成」。

### `--split-dir`

账本默认写在 pair 的 state 文件旁边。`--split-dir` 可以覆盖，测试和「把账本放到
NAS 上」都靠它；优先级是 `--split-dir` > state 文件所在目录 > 用户配置目录。

## 12. 全局设置

`settings.json`（`os.UserConfigDir()/weftsync/`）保存 daemon 级设置，与 job 文件分开：
job 文件说「同步什么」，这里说「程序怎么表现」。文件缺失=全新安装（不是错误），
文件损坏=记一行日志后用默认值继续（不能让坏文件阻止同步）；写入是原子的，权限 `0600`。

| 字段 | 作用 |
|---|---|
| `notify_enabled` | 是否弹托盘通知。默认开。**每次通知都检查它**，而不是只在界面隐藏复选框 |
| `exclude` | 追加到每次运行的过滤器上，对所有作业生效。**只能排除**，不能把作业排除掉的文件加回来 |

界面在「设置」页：`GET/POST /api/settings`，保存后立即生效，无需重启。
没有托盘时 `notifications_available` 为假，界面显示说明而不是一个点了没用的开关。
