## Core Principles

### I. 验证优先于断言（VERIFIED, NOT ASSUMED）

任何「已完成 / 已修复 / 已生效」的结论，必须附**可复现的证据**：命令原文与输出、
测试结果、或运行时观测值。

禁止以下推断链路：
- 「改法看起来对」→ 宣布修好
- 「文件已落盘」→ 宣布产物可用
- 「反向工程出机制」→ 宣布配置生效

**必须验证到实际链路里**：配置被加载、函数被调用、产物被消费。

理由：历史上多次因「未验证就宣称完成」返工，代价远高于多跑一条命令。

---

### II. 计划落盘，逐步汇报（PLAN ON DISK）

- 计划写在仓库内 `PLAN.md`，**每完成一步就更新**，不只在对话里说
- `PLAN.md` 只放计划；**决策理由另开** `docs/decisions.md`
- 每完成一个步骤就停下汇报，不一口气做到底后一次性交付

理由：对话会滚动丢失，磁盘文件是可审阅的状态载体。

---

### III. 产物必须由脚本可复现（REPRODUCIBLE BY SCRIPT）

凡下载、生成、导出、清理类操作，都要写成**幂等脚本**；手敲命令不算交付物。

判断标准：清空产物目录后，重跑脚本能完整恢复，且结果一致。

理由：曾因误删 35 个报告文件，靠脚本重跑全部恢复 —— 手工操作无法重建。

---

### IV. 清除类操作按内容特征扫描（NO FIXED NAME LISTS）

删除 / 覆盖 / 迁移文件时，**禁止依赖手写文件名清单**。

必须：
1. 先按内容特征或结构特征匹配出待处理集合
2. **打印匹配结果**
3. 人工核对后再执行

理由：曾把 `attribute.py` 拼成 `attribution.py` 漏删，也漏过不在模式内的文件。

---

### V. 工作区边界与最小闭环（BOUNDARY & YAGNI）

- **不向工作区外写任何文件**（含 `%TEMP%`）；临时产物统一放 `.scratch/`
- 外部参考代码必须复制/克隆到工作区内
- 先做能跑通的最小闭环，再扩展；不为假想需求预先抽象

理由：越界写入会被拦截并要求人工审批；过早抽象会在方向确定后全部作废。

## 技术约束（随方向确认后补充）

| 项 | 约定 |
|---|---|
| Shell | PowerShell 5.1，命令用 `;` 串联，不用 `&&` |
| 脚本编码 | `.ps1` 一律纯 ASCII（GBK 解析下中文会报误导性错误）；中文只放 Markdown |
| 终端输出 | 中文输出由工具自己写 UTF-8 文件，不依赖终端管道 |
| 版本控制 | 仓库内统一 LF（`.gitattributes`）；主分支 `main` |
| 仓库位置 | OneDrive 同步目录内，`.git` 可能被同步进程锁定 |

> 技术栈、测试框架、目录结构等**待 `PLAN.md` Q1–Q4 确认后**再写入本节。

## Governance

- 本宪法优先于其他实践约定；冲突时以本文件为准
- 修订需：提出理由 → 记录到 `docs/decisions.md` → 更新版本号
- 版本号语义：MAJOR = 原则增删或语义反转；MINOR = 新增条款；PATCH = 措辞修正
- 每个 feature 的计划（`plan.md`）必须声明与本章程的符合性；违反须在
  Complexity Tracking 中说明理由
